# Bug audit — connection errors and app flows

**Date:** 2026-11-09<br>
**Scope:** the running board (one LiveView at `/` with panels in the query
string, the JSON API, the supervised processes) and the live service log.<br>
**Method:** the live log read back to its start (78k lines, 2026-11-05 to
2026-11-09); a worktree server on port 4700 against a *copy* of the dev database,
without GitHub or model keys, driven by headless WebKit over a URL matrix and
every safe control; a read-only static pass whose findings were kept as
hypotheses until reproduced.<br>
**Workflow:** Elixir Agent Kit 0.8.0 `debugging` (large).

The live service on 4099 and its database were only read. Red actions were not
executed against GitHub or the runner.

## States

`investigating` · `confirmed` · `fixed` (code and test) · `validated` (seen
working in the running app) · `blocked`.

## Details

### B01

- **Flow:** opening Logs, or any URL with `panel=logs`.
- **Reproduce:** a board log holding a byte that is not UTF-8, then `/?panel=logs`.
- **Expected:** the sheet lists warnings and errors.
- **Observed:** `NOT-CONNECTED` for 30 s, more than 200 reconnects per URL, 425
  `GenServer terminating` in three minutes of sweep.
- **Evidence:** live log, 2026-11-09 09:58:47 on: `(Jason.EncodeError) invalid
  byte 0xE3` in `"… a voz não foi gerada (HTTP 400)"`, from
  `Phoenix.Socket.V2.JSONSerializer`, label `Phoenix.LiveView, BoardLive`, last
  message `show_panel logs` or the `phx_join` of `?panel=logs`.
- **Cause:** two owners. `launchd` starts the service without a locale, so the
  BEAM's standard output is Latin-1 (`env -i elixir` reports `:latin1`, with
  `LANG=en_US.UTF-8` `:unicode`), and `AgentBoard.Logs` handed those bytes to
  the socket as text. The URL keeps the panel, so each reconnect joined and
  crashed again until the tab was closed.
- **Fix:** `Logs` reads a line that is not UTF-8 as Latin-1, so the bytes
  already in the file open too; `scripts/service.sh` sets `LANG`.
- **Validated:** `logs_test.exs` and `logs_panel_test.exs` (failed before);
  on the running app, a copy of the real log opens with 127 entries, one socket
  and no crash. The service only picks up `LANG` at its next restart.

### B02

- **Flow:** the sheet is open and a superagent changes state (ticker, every 30 s).
- **Observed:** `FunctionClauseError` in `Phoenix.Component.assign/2`, last
  message `:superagents_changed`.
- **Cause:** `assign(:logs_sources, ...)` without the socket in
  `BoardLive.handle_info(:superagents_changed, ...)`.
- **Fix and validation:** the socket is passed; `logs_panel_test.exs` failed
  before. On the running app, a state change during an open sheet leaves it
  connected.

### B03

- **Flow:** `/?repo[a]=b`, `/?repo[]=x`, `task[a]=1`, an id past bigint, a NUL
  byte in the slug.
- **Expected:** the board opens without the panel.
- **Observed:** 500 from the dead render (`String.split/3`, `String.Chars`,
  `DBConnection.EncodeError`, `Postgrex.Error`).
- **Cause:** the URL reached the database layer unchecked.
- **Fix:** `Board.repository_by_slug/1` takes only a usable string and
  `Board.parse_id/1` is the one reader of an outside id (navigation, `open_any`,
  `PATCH /api/tasks/:id`).
- **Validated:** `board_url_params_test.exs` (14 URLs) and the same URLs on the
  running app.

### B04

- **Flow:** on Hoje, click the project the board last showed.
- **Observed:** nothing happens, and the rail marks that project as current.
- **Cause:** the "same repository" guard in `handle_event("select", ...)` did
  not look at the view.
- **Fix and test:** `today_test.exs`.

### B05

- **Flow:** any board load where a workpad has no validation.
- **Evidence:** `FunctionClauseError` in `LocalCI.workpad_state(nil, sha)`, ten
  times in the live log on 2026-11-08 and 09.
- **State:** already fixed on `main` before this audit (`workpad_status(nil, _)`);
  the sweep over real data did not hit it.

### B06

- **Flow:** a comment or body on a `ready` task quoting
  `https://github.com/a/b/pull/9999999999`, or a ticket following that thread.
- **Observed (test):** `DBConnection.EncodeError` from the int4 `number` columns,
  inside the load that every page runs.
- **Cause:** numbers read from text went to queries unchecked.
- **Fix:** `GitHub.number/1` is the one reader of a number from text or from the
  runner (`Board`, `Workpad`, `Attribution`, `LocalCI`, `AgentState`).
- **Validated:** `board_workpad_test.exs`, `github_number_test.exs`. Not seen in
  real data; found by reading and reproduced in a LiveView test.

### B07

- **Flow:** the runner's JSON with a field in another shape: a non-numeric channel
  number, `assignments` as an object, `ended` or a report as text, a summary that
  is not text.
- **Observed (test):** `ArgumentError`, `BadMapError` or `FunctionClauseError`
  during every load, for every repository.
- **Cause:** `AgentState.normalize/1` trusted the shape of data another program
  owns and versions.
- **Fix:** a field in another shape reads as absent; the row stays.
- **Validated:** `agent_state_test.exs`, `board_workpad_test.exs`. Not seen in
  real data.

### B08

- **Flow:** a superagent manager answering `/state` with something that is not the
  expected object (a proxy's HTML, `{"health":{"uptime":3}}`).
- **Observed (reading):** the exception runs in a `Task.async_stream` task linked
  to the ticker, whose `rescue` cannot catch an exit; the ticker restarts and
  ticks after 1 s, past the supervisor's limit of three restarts in five seconds.
- **Fix:** `DshManager.observation/1` answers an observed error.
- **Validated:** `superagents_test.exs` (the shape). The supervisor cascade was
  not run.

### B09

- **Flow:** the composer's split, unchecking every proposed task.
- **Observed:** a form with no box checked sends no `tasks`, so the last choice
  stayed and the button still said "Pôr 1 na fila". Sending opens a real issue.
- **Fix:** the form always sends a blank `tasks[]`.
- **Validated:** `composer_test.exs`; on the running app the button reads "Pôr 0 na
  fila" and is disabled.

### B10

- **Flow:** typing a question in the inspector, then changing tab or losing the
  socket.
- **Cause:** the form had only `phx-submit`, so the text lived in the DOM alone,
  and LiveView recovers only forms with `phx-change`.
- **Fix:** `ask_change` keeps the draft, which belongs to the task it was typed
  on.
- **Validated:** `inspector_test.exs`; on the running app the draft survives a tab
  change and a forced reconnect, and another task opens empty.

### B11

- **Flow:** preparing a blocker task, then "Voltar e editar".
- **Observed:** the form closed and reopened with the generated defaults, and the
  person's no left no row, against the Board actions contract.
- **Fix and test:** the edits are kept, the form returns and the refusal is a
  `declined` decision (`inspector_test.exs`).

### B12

- **Flow:** pausing or scaling a superagent another tab has just removed.
- **Fix and test:** `KeyError` on `nil` becomes a message
  (`superagents_panel_test.exs`).

### B13

### B15

- **Evidence:** five `HTTP 400` from `/api/voice/stream` on 2026-11-09 at 08:50, each
  in under 200 ms, with engine `mixed`, Flash v2.5, speed 1.10.
- **Open:** the body was dropped, so the reason is unknown. Reproducing needs the

- **Instrumented:** the log now carries ElevenLabs' own code
  (`elevenlabs stream status=400 code=…`) and never its message, which can quote the

### B16

- **Flow:** a board with no repository. The empty state says to open
  Configurações → Repositórios.
- **Observed:** the Settings button does nothing, so a first repository could only
  be added through the API.
- **Cause:** `BoardNavigation` required a repository for that panel.
- **Fix:** landed on `main` at the same time, in the language selection change
  (sallaumen/dsh-supergent-superboard#441); this round keeps the test.
- **Validated:** `board_url_params_test.exs`; on the running app with an empty
  database, Settings opened and the first repository was added.

### B17

- **Flow:** Configurações → Versão → "Atualizar e reiniciar" on an update that
  changes `mix.lock`, a config file or adds a migration.
- **Reproduce:** a clone one commit behind a local `origin`, the service's dev
  environment, click the button.
- **Expected:** the old node keeps answering while the new build is prepared,
  then restarts.
- **Observed:** the page reloads 0.8 s after the click and every request answers
  500 from then on (`could not compile application … mix.lock`). No build, no
  marker, no restart. The live board stayed like that from 10:48 on 2026-11-09,
  and the button that would fix it is on the page that no longer opens.
- **Cause:** two faults on the same moment. The pipeline was `start_async` on the
  LiveView, and the fast-forward's own live reload ended that LiveView and the
  task with it, silently. And the dev-only `Phoenix.CodeReloader` and
  `CheckRepoStatus` refuse every request once the files changed, so "the old node
  keeps answering" did not hold.
- **Fix:** `System.UpdateRun` runs the pipeline in a supervised task any board can
  follow, and holds the two dev checks (`AgentBoardWeb.DevReload`) from before the
  pull. A failure after the pull keeps them held, so "Reiniciar" stays reachable.
- **Validated:** `update_flow_test.exs`, and the same click in the clone: 200 on every
  request for the 31 s of the pipeline, the new build prepared, the migration applied
  and the node restarted, against 500 from 3 s on without the fix. The clone ran before
  sallaumen/dsh-supergent-superboard#442 landed; that change restores the config
  files' times and is kept, and the pipeline tests ran with it.
- **Left as is:** the WebSocket handshake still asks the reloader and logs the same
  error, without failing the connection.

### B18

- **Flow:** the boot that promotes a prepared build, in `scripts/service.sh` and in
  the detached restart script.
- **Observed:** `mv: rename _build/next to _build: No such file or directory`, exit 1.
  `_build/next` sits inside `_build`, which had just been moved aside. It also aimed
  at `_build`, where Mix does not look for a build: the environment's is `_build/dev`.
  The live board had not reached this path yet, because B17 stopped earlier.
- **Fix:** the build moves to `_build/$MIX_ENV` and the old one to `_build/prev`; a
  marker without its build no longer lingers.
- **Validated:** `updater_test.exs` runs the shell snippet on a real tree, and a clone
  booted through `service.sh` with no locale.

### B19

- **Flow:** a request title from a person, the API or a model past 255 characters; the
  `create_error` event carrying it; the decision row of a refused repository name.
- **Observed (test):** `Postgrex.Error … value too long`, raised and not returned.
- **Fix:** the title is clipped before GitHub and the row, event and decision subjects
  are clipped, and `Repository` refuses a longer owner or name with a changeset.
- **Validated:** `create_request_test.exs`, `actions_test.exs`.

### B20

- **Fix and validation:** a transcript continues the draft on a new line
  (`composer_test.exs`, and the running app). A transcript arriving while the textarea
  has focus still waits for it to lose focus: LiveView does not patch a focused input.

### B21

- **Fix and test:** those two panels open without a repository
  (`board_url_params_test.exs`).

### B22

- **Observed:** source rows ended at x = 430 inside a 320 px popover, past a 375 px
  screen: the list had a `max-content` column.
- **Validated:** no element past the popover at 375 and 1280 px.

### B23

- **Observed:** on the running app the chip read "11:11" while its popover read "14:11"
  and "14:15"; the voice feed's clock was UTC too, with no label.
- **Fix and test:** both take the browser's offset (`freshness_beacon_test.exs`,
  `voice_activity_feed_test.exs`, which failed before). Times labelled "UTC" stay.

### B24

- **Flow:** the node restarts while `Usage.Worker` (`max_attempts: 1`, every five
  minutes) is executing.
- **Observed:** on a server whose copied database held that job, the boot logged
  `could not rescue orphaned Oban jobs: … violates check constraint "attempt_range"`.
- **Cause:** `ObanRescue` added one to `attempt`, which Oban had already counted, and
  did it in a single update: one job at its limit failed the sweep for all of them.
- **Fix and test:** retryable while attempts remain, discarded otherwise, with no
  extra count (`oban_rescue_test.exs`). The earlier test asserted the extra count; it
  now asserts the attempt stays.

## Retries and failure messages

Measured on the board's own events, 2026-11-02 to 2026-11-09: 2,080 `sync_error`, of
which 1,431 rate limits and 637 HTTP 404, plus 218 item errors. Real blips were few: 10
closed sockets, 2 5xx, 2 DNS failures, 1 timeout. Model calls: 9 errors, slowest 15.5 s.
The policy now in force is the table in the maintainer contract's "Network paths".

### B25

- **Observed:** `Sync.all/1` discarded each result and `Sync.Worker` returned `:ok`, so
  the "Oban retries" of the contract never happened, and its rate-limit `rescue` was
  dead code (it would also have snoozed with a string).
- **Fix and test:** `Sync.run/1` returns the results and the worker answers with them
  (`sync_worker_test.exs`, which failed before).

### B26

- **Observed:** after the first 403/429 the sync still asked for reviews and checks of
  every other pull: 36 to 39 events in a run, on top of the refusals. The popover then
  said "No connection to GitHub", which reads as something to fix.
- **Fix and test:** a rate limit ends the run; `Atrasado` / `Limitado` on the panel
  (`sync_repo_test.exs`, `freshness_test.exs`, `freshness_beacon_test.exs`).

### B27

- **Fix and test:** a 403 counts as a rate limit only with GitHub's evidence; the wait
  comes from `Retry-After` or the quota's reset time (`github_retry_test.exs`).

### B28

- **Fix and test:** reads and closing an issue repeat twice; a write that may have
  landed is never repeated, so a retry cannot open a second issue
  (`github_retry_test.exs`). Not exercised against the real GitHub.

### B29

- **Evidence:** seven `sync_error` with `unknown registry: AgentBoard.PubSub`: Oban
  started before PubSub. **Fix:** PubSub first. No test; the boot log is the check.

### B30

- **Evidence:** the 1,431 + 637 refusals came on top of 24 healthy syncs an hour, the
  live board's own count. Both repositories, unauthenticated-looking (404 on private
  repositories, the 60-second default). Inference: dev servers from worktrees, no token,
  on the shared database. Their `sync_error` is the newest attempt the live panel reads.
- **Fix and test:** with no token the job cancels without writing (`sync_worker_test.exs`).

### B31

- **Fix and test:** `AgentBoardWeb.FailureText` replaces `inspect/1` in the panel's
  failure messages (`failure_text_test.exs`). The JSON API keeps its detail.

### B32

- **Evidence:** 1 failure in 9 full runs (seed 303), in `agent_state_test.exs`:
  `table ticket already exists`.
- **Cause:** the test named its SQLite files with `System.unique_integer/1` and never
  removed them. That integer restarts with the VM, so a later run could open a file
  left by an earlier one. `/tmp` held 188 pairs of them.
- **Fix and validation:** the names carry the OS pid and the files are removed on
  exit; `runners_test.exs` and `actions_test.exs` leaked the same way and now clean
  up. Seed 303 passes, and the count of these leftovers did not grow across a run.
- **Not explained:** two earlier full runs failed tests that later passed (four in
  one, five in the other). The names of the five were lost and the four do not touch
  these files, so this fix is not claimed for them. Six of the nine runs above were
  under load and none reproduced them.

### Rejected

Candidates that the evidence did not support, so no change was made:

- A commit subject that is not UTF-8 reaching the running card. Git converts such
  a message to UTF-8 when it commits; the regression test passed without any fix.
- AI calls blocking past LiveView's 30 s push timeout. `ai_calls` holds 104 real
  calls, the slowest 15.5 s. Update, split and unblock suggestions are already
  asynchronous.

## Coverage after the second pass

Also exercised on the running app, with no crash in the log: phone width on every
panel, the long-polling transport on the board, Logs, composer, inspector and Hoje, and
a real sync broadcast while a draft was being typed.
