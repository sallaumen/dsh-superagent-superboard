# Shared practice ownership and migration

Elixir Agent Kit owns reusable practices. Agent-board consumes an immutable tag
and reads the library directly from the Mix dependency through the
[installed index](../../.elixir-agent-kit/START.md). Run `mix deps.get` first.
There is no editable mirror and no per-skill native registration in this project.
The v0.3 routing guide groups workflows by frontend, backend, cross-cutting
engineering and delivery; each workflow states quality and validation criteria.
Since v0.3.1 it also routes HUD, menu and overlay work in a game or canvas
scene to one pinned external skill, `game-ui-ux`; the board has no such scene.

## Where a rule belongs

| Content | Canonical owner |
|---|---|
| Shared contract, workflows, general Elixir guidance, reusable templates | [Elixir Agent Kit](https://github.com/sallaumen/elixir-agent-kit/tree/main/priv/library) |
| Board data, AI calls, sync and network behavior | [Maintainer contract](../maintainer-contract.md) |
| Board delivery and validation commands | [CONTRIBUTING.md](../../CONTRIBUTING.md), [PIPELINES.md](../../PIPELINES.md) |
| Collaboration and executor setup | [Agent documentation](how-it-works.md), [collaboration](collaboration.md) |
| Installed index and ownership state | Generated by `mix agent_kit.sync`; never author guidance here |

Use the kit's [evolution policy](../../deps/elixir_agent_kit/priv/library/EVOLUTION.md)
for a reusable improvement discovered while working here. Keep a sanitized problem,
proposed rule and counterexample, contribute upstream under the current publication
authority, release, then adopt through a pinned dependency PR. Local product facts
stay local. Do not publish private contexts as community rules.

Run `mix agent_kit.outdated` during explicit dependency maintenance. It queries
public stable Git tags without changing the checkout. `--check` fails on a newer
tag. Network failure means freshness is unknown. There is no background updater.
`mix agent_kit.check` verifies local references only, not latest-release freshness.

## Disposition of the original library

The complete original collection remains recoverable at commit
`f5b03770161334b7ed2e5ee9876e319a6f4ec369` in this repository. For example:
`git show f5b03770161334b7ed2e5ee9876e319a6f4ec369:capabilities/contrato.md`.
Git history preserves it without a second active copy or an archive agents might
mistake for current rules.

| Former paths | Disposition |
|---|---|
| `capabilities/skills/`, catalog, manifest | 33 reviewed English workflows in kit `priv/library/skills/`; original-to-public mapping and source-review matrix in its `docs/`. This is adaptation, not literal equivalence. |
| `contrato.md`, `parametros.md` | Kit shared contract and per-workflow inputs/modes; board-specific authority remains local. |
| `templates/` | Kit decision, delivery-plan, diagnosis, validation and practice-proposal templates. |
| `INCORPORACAO.md`, usage/source references | Original provenance remains in Git; current mapping and evolution policy live in the kit. |
| `validacao/casos-de-avaliacao.*` | 29 routing cases adapted to public IDs and 11 new coverage cases in kit `evals/`, outside runtime guidance. Private context names removed; E27 corrected to respect explicit merge/deploy authority. |
| `validacao/fixtures/`, historical validation report | Historical evidence retained in Git; not represented as new evaluation results. |
| `tools/` | Retired local validator; shared-content/installer checks run in kit CI. This project checks its actual installation through Mix. |
| `contextos/elixir-phoenix-oban.md` | General guidance adapted in kit `ELIXIR.md`; installed technology and local contracts govern use. |
| Other `contextos/` | Historical product intentions retained in Git, not current board rules or proof of another application's behavior. No private contexts exported. |
| `capabilities/README.md` | One redirect for old navigation; no active library remains here. |

The v0.2 sync removes the old generated library and native wrappers using their
recorded checksums. Modified generated content blocks migration before writes;
unrelated skills and text outside instruction blocks are preserved. Commit the
tag, lock, index/state and deletions together. Fresh worker checkouts must fetch
dependencies and permit direct reads of ignored `deps/` files. Live client loading
still needs a fresh-session check; filesystem validation alone does not prove it.
